現在のブランチからGitHub PRを作成してください。

## 補足情報

$ARGUMENTS

## 手順

### 1. 状態の把握

以下を並列で実行:

- `git status` — 未コミットの変更がないか確認
- `git branch --show-current` — 現在のブランチ名
- `git remote -v` — リモートの確認
- `gh repo view --json defaultBranchRef --jq '.defaultBranchRef.name'` — デフォルトブランチ名を動的に取得

デフォルトブランチ名（`main` または `master` 等）を取得したら、以下を実行:

- `git log --oneline <デフォルトブランチ>..HEAD` — ベースブランチからの全コミット
- `git diff <デフォルトブランチ>...HEAD --stat` — 変更ファイルの統計

### 2. 事前チェック

- **未コミットの変更がある場合**: ユーザーにコミットするか確認する
- **デフォルトブランチにいる場合**: 新しいブランチを作成するか確認する
- **リモートに push されていない場合**: `git push -u origin <branch>` で push する
- **既に PR が存在する場合**: `gh pr view` で確認し、ユーザーに知らせる

### 3. 変更内容の分析

- `git diff <デフォルトブランチ>...HEAD` で全差分を確認
- 全コミットメッセージから変更の全体像を把握（最新だけでなく全コミット）
- 変更の種類を判断（新機能 / バグ修正 / リファクタ / ドキュメント 等）

### 4. ドラフト判断

以下のいずれかに該当する場合は `--draft` を付ける:

- 作業が明らかに未完了（TODO コメント多数、テスト未実装など）
- 補足情報に「draft」「WIP」「作業中」などが含まれている
- コミット数が1件で「WIP」「仮実装」などのメッセージになっている

### 5. PR の作成

`gh pr create` で PR を作成する。ベースブランチは手順1で取得したデフォルトブランチを使用する。

#### タイトル

- 70文字以内
- 変更の本質を簡潔に表現
- 日本語で書く

#### 本文

以下のフォーマットで HEREDOC を使って作成（**日本語**で記述）:

```
gh pr create --title "PRタイトル" --base <デフォルトブランチ> --body "$(cat <<'EOF'
## 概要
- 変更点1
- 変更点2
- 変更点3

## 変更の背景・理由
（なぜこの変更が必要だったかを簡潔に）

## テスト計画
- [ ] テスト項目1
- [ ] テスト項目2

## 注意事項（任意）
（レビュアーへの補足、破壊的変更がある場合はここに記載）

Generated with Claude Code
EOF
)"
```

#### オプション

- ベースブランチが引数で指定されていれば `--base` でその値を使用
- ドラフト条件に該当する場合は `--draft` を付ける
- レビュアーを指定したい場合は `--reviewer <username>` を追加（引数で指示があれば）
- ラベルを付ける場合は `--label <label>` を追加（引数で指示があれば）

### 6. 結果報告

```
PR作成完了
━━━━━━━━━━━━━━━━━━
URL: （PR の URL）
タイトル: （PRタイトル）
ベース: （ベースブランチ） <- （ヘッドブランチ）
変更: （ファイル数、追加/削除行数）
ドラフト: （Yes / No）
━━━━━━━━━━━━━━━━━━
```
