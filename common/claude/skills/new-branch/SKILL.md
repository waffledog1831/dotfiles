---
name: new-branch
description: 作業開始前に main の最新を取り込み、main からブランチを作成する。
argument-hint: "[オプション: ブランチ名 or 作業内容の要約]"
---

これから始める作業のために、mainブランチを最新化してから新しいブランチを作成してください。

## 補足情報

$ARGUMENTS

## 手順

### 1. 現在の状態確認

以下を並列で実行:

- `git status` — 未コミット・未追跡の変更がないか確認
- `git branch --show-current` — 現在のブランチ
- `gh repo view --json defaultBranchRef --jq '.defaultBranchRef.name'` — デフォルトブランチ名を動的に取得（`gh` が使えない場合は `main` を既定値とする）

### 2. 未コミットの変更がある場合

作業ツリーが汚れている状態でブランチを切り替えると意図せず変更が混ざる可能性があるため、以下をユーザーに確認する:

- コミットしてから進める
- 一旦 `git stash` してから進める（ブランチ作成後に `git stash pop` するかは別途確認）
- このまま強行する（変更がコンフリクトしなければ多くの場合そのまま持ち越される）

ユーザーの指示なしに `git stash` や `git reset` などの破壊的操作を実行しない。

### 3. main の最新化

- `git fetch origin`
- `git checkout <デフォルトブランチ>`
- `git pull origin <デフォルトブランチ>`

### 4. ブランチ名の決定

- 引数でブランチ名が明示されていれば、それを正規化して使う（スペース→ハイフン、英数字とハイフン以外は除去）
- 明示されていない場合、補足情報や直前の会話の作業内容から `<種別>/<内容の要約>` 形式で提案する
  - 種別の例: `feat`, `fix`, `chore`, `docs`, `refactor` （commitスキルのprefix一覧に準拠）
  - 例: `feat/user-auth`, `fix/pagination-bug`
- ブランチ名の候補をユーザーに提示してから作成する（明示指定がある場合は確認不要）

### 5. ブランチ作成

```bash
git checkout -b <ブランチ名>
```

### 6. 結果報告

```
🌿 ブランチ作成完了
━━━━━━━━━━━━━━━━━━
ベース: （デフォルトブランチ、最新化済み）
新ブランチ: （作成したブランチ名）
━━━━━━━━━━━━━━━━━━
```
