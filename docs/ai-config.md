# AI 設定の設計と確認

## 方針

- 常時指示は個人の好み、作業境界、プロジェクト固有の制約に絞る。
- スキルには固有の手順を置き、一般論や定型報告を繰り返さない。
- キャラクターは短い人格設定を残し、独立した文脈が有益な場合にだけ役割を使う。
- 確実に制限したい操作は権限設定で扱う。自然言語の指示だけをアクセス制御とみなさない。

短いこと自体を品質の指標にしない。指示の矛盾を減らし、目的・制約・完了条件を優先する。

## 使用時の比較

同じ種類の依頼で、変更前後の結果、不要な確認の回数、委任の回数、所要時間を比較する。
次のケースを確認し、うまくいかない場合は失敗に必要な指示だけを戻す。

- 小さな修正を不要な委任なしで完了できる。
- 未コミットの無関係な変更を保持して新規作業できる。
- PR レビューだけの依頼で投稿・承認しない。
- PR 作成依頼では関連変更のコミット・push・作成まで進む。
- 役割を指名するとキャラクターを維持し、レビュー役は編集しない。
- スキルなしでできる作業と、スキルによって固有の手順を守れる作業を区別できる。

構文・配置チェックは設定の妥当性を確認するもので、モデルの品質改善を証明しない。
