# 冒険者ギルド「Arcana」 — エージェント一覧

> 冒険者ギルド「Arcana」をテーマにしたマルチエージェントシステムです。
> メインセッション（アイ）が司令塔となり、タスクに応じて冒険者（サブエージェント）を編成してクエストを遂行します。

## 設計方針

「使いこなせる最小構成」を重視し、**専任の冒険者は 4 体に絞っています**。ドキュメント整備やインフラ構築のような「やり方の知識」はサブエージェントではなくスキル（`/docs`・`/devops`）で対応します。

- **必ず守らせたいルール** → Hooks / permissions（`settings.json`）
- **やり方の知識** → Skills（`/docs`・`/devops` など）
- **独立した文脈で任せたい専門作業** → Subagents（下記 4 体）
- **常時効かせる方針** → CLAUDE.md

## システム構成

```
アイ（メインセッション＝司令塔）
  ↓ 自動委任 / 明示指名で冒険者を編成
┌─────────────────────────────────────────────┐
│  冒険者リリア（lilia）— 実装・修正・テスト・改善 │
│  斥候シオン（sion）    — 探索・調査            │
│  賢者オルドス（ordos） — レビュー・設計         │
│  符術師ルカ（luca）    — セキュリティ           │
└─────────────────────────────────────────────┘
  ＋ ドキュメント整備 → /docs スキル
  ＋ インフラ・CI/CD  → /devops スキル
```

> **ポイント**: 各冒険者の `description` は「どんなときに呼ぶか」を明記した**呼び出しルール**として書いてあります。これにより、アイが文脈に応じて**自動で**適切な冒険者に委任できます。もちろん明示指名（`@sion` など）も可能です。

## スキルで対応する領域

以下は専任冒険者を置かず、スキルとして実装担当（リリア）やアイが呼び出します。

| 領域 | スキル | 内容 |
|------|--------|------|
| ドキュメント | `/docs` | README・API仕様書・ユーザー向けドキュメント・CHANGELOG の作成/更新 |
| インフラ・CI/CD | `/devops` | CI/CDパイプライン・Docker・デプロイ設定・環境構築・自動化 |

## 使い方

### 基本の流れ

アイに普通に依頼するだけです。タスク内容と各冒険者の `description` から、アイが自動で適切な冒険者に委任します。

```
このバグを調査して修正して       → シオン（調査）→ リリア（修正）
このコードをレビューしてほしい     → オルドス
認証まわりのセキュリティを見て     → ルカ
```

### 明示指名

特定の冒険者を直接呼びたいときは名前で指名できます。

```
@sion この関数の使用箇所を洗い出して
@ordos この設計方針をレビューして
```

### 永続メモリ

全冒険者は `memory: project` が有効で、プロジェクトごとの知見を蓄積します。

> エージェントチーム機能（`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`）は使いません。4 体編成では冒険者同士を協調させるより、アイが順に委任する方がシンプルで挙動も安定するためです。

### worktree 並列運用

同一ファイルを複数の冒険者が編集する可能性がある場合や大規模クエストでは、`isolation: "worktree"` を使って冒険者ごとに独立した git worktree で作業させます。

- 各冒険者が独立ブランチで作業するため、ファイル競合を気にせず並列化できる
- 作業完了後、マージ順序を調整し、オルドスのレビューを経て統合する
- 変更がなければ worktree は自動で削除される

## 冒険者の追加

`claude/agents/{キャラクター名}.md` を作成してください。
`claude/agents/TEMPLATE.md` にコメント付きのテンプレートがあります。コピーして必要箇所を埋めてください。

```bash
cp claude/agents/TEMPLATE.md claude/agents/{キャラクター名}.md
```

> **追加時の注意**: `description` は「どんなときに呼ぶか」を具体的に書くこと。曖昧な自己紹介文だと自動委任が効きません。増やしすぎると使いこなせなくなるため、本当に独立した文脈が必要な専門作業に絞りましょう。「やり方の知識」はスキルで足ります。
