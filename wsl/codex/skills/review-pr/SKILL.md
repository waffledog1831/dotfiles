# PR レビュー

- 指定 PR のベース・最新 head SHA・説明・差分・関連コード・既存レビューを確認する。
- 変更が引き起こす具体的な不具合を優先する。セキュリティ、互換性、性能、テスト不足を影響に応じて確認し、好みだけの修正を要求しない。
- 指摘には重要度、ファイルと行、問題が起きる条件、影響を添える。推測だけの指摘や既存レビューとの重複を避ける。
- 大きな PR は影響とリスクに基づいて調査を分割する。サイズだけで確認対象を切り捨てず、未確認範囲があれば明記する。
- 通常は結果をユーザーに返す。GitHub へのコメント・レビュー投稿は、その投稿が依頼に含まれる場合だけ行う。
- 投稿時は head が変わっていないか再確認する。インラインコメントは diff 上の実ファイル行番号と LEFT / RIGHT を使い、不確かな行は本文に書く。
- 承認・変更要求は依頼された場合だけ行う。それ以外の投稿は COMMENT とする。自分の PR を APPROVE しない。
- 指摘がなければその旨と検証範囲を伝え、問題が存在しない保証とはしない。
